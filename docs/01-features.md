# JinFarm 기능 명세서 (초안)

> 여러 농가가 함께 쓰는 **실외 노지 밭** 스마트팜 관리 서비스
> 작성일: 2026-09-29 · 상태: 초안 (v0.6)

## 1. 개요

여러 농가가 가입해 각자의 농장을 등록하고 관리하는 **멀티 농장 웹 서비스**.
농장의 밭을 **구역(Zone)** 단위로 나누고 구역마다 서로 다른 작물을 심는다.
구역별 토양 상태와 현장 기상을 센서로 수집하고 기상 예보와 함께 보여주며,
**사용자가 직접 정의한 작물 정보**를 기준으로 이상 상황을 **카카오톡**으로 알려주고, 작물별 재배 이력과 수확량을 기록한다.
관수(물 주기) 자동 제어는 관수 설비가 갖춰지는 **2단계**에서 추가한다.

### 개발 전략

- **1단계는 실제 장비 없이 개발한다.** 서버에 내장된 **장치 시뮬레이터**가 가짜 센서 데이터를 만들어 보낸다 (2.8 참고).
- 시뮬레이터는 실제 장비와 **같은 통신 규격**을 쓴다. 나중에 실제 장비로 바꿔도 서버 코드는 바뀌지 않는다.
- 현장 통신 방식(Wi-Fi / 실외 AP / LoRa)은 실제 장비 도입 시점에 결정한다.

### 파일럿 농장 현황

서비스의 첫 사용 농장. 설계의 기준 사례로 삼는다.

산지 경사면에 떨어져 있는 **밭 3곳**, 총 약 **2,177㎡ (약 659평)**.

| 밭 | 면적 | 평 환산 | 위치 |
|---|---|---|---|
| 밭 A (윗밭) | 1,552.96㎡ | 약 470평 | 북쪽, 도로(방죽로) 옆, 가장 넓음 |
| 밭 B (중간밭) | 478.63㎡ | 약 145평 | 농로 남쪽, 건물(337-112) 바로 옆 |
| 밭 C (아랫밭) | 145.38㎡ | 약 44평 | 남서쪽, 건물 아래 |

| 항목 | 현황 |
|---|---|
| 전기 · 인터넷 | 건물(337-112)에 **둘 다 있음** → 현장 게이트웨이 설치 거점 |
| 현장 통신 | 밭 A는 Wi-Fi가 닿지 않을 가능성 높음 → **실제 장비 도입 시 결정** |
| 물 | **지하수** (펌프 필요) |
| 관수 설비 | 미정 (스프링클러/점적 등은 추후 결정) |
| 작물 | 과수(살구, 포도) + 채소(상추, 깻잎, 양파, 파, 호박, 수박 등) 혼합 |

설계에 미치는 영향:

- **밭이 여러 곳으로 나뉠 수 있음** → 농장과 구역 사이에 **밭(Field)** 단위를 둔다.
- **건물에 전기·인터넷 있음** → 건물에 **게이트웨이**(예: 라즈베리파이)를 두고, 밭의 센서 노드는 게이트웨이를 거쳐 서버와 통신하는 구조를 기본으로 한다.
- **지하수 사용** → 2단계 관수 제어 시 **지하수 펌프 ON/OFF**가 모든 관수의 전제 조건이 된다.
- **경사지** → 넓은 밭은 구역을 여러 개로 나누고 센서를 2개 이상 둔다.
- **과수와 채소가 섞여 있음** → **다년생**과 **일년생**을 모두 다뤄야 한다 (2.3 참고).

### 실외 밭이라서 달라지는 점

| 구분 | 실내/온실 | 실외 밭 (이 프로젝트) |
|---|---|---|
| 온도·습도 | 히터·가습기로 **제어** | 제어 불가 → **관측·예보·경보** 대상 |
| 핵심 제어 | 공조, 조명 | **관수** (지하수 펌프 + 구역별 밸브) — 2단계 |
| 외부 데이터 | 거의 불필요 | **기상 예보** 필수 (서리 경보, 비 오면 관수 생략) |
| 전원 · 통신 | 상시 전원, Wi-Fi | 건물 근처는 상시 전원, 먼 밭은 배터리/태양광 + 무선 |
| 장비 | 실내용 | 방수·방진, 동파 대비 |

### 핵심 개념

```
사용자(User) ──< 농장 멤버십(Membership: 역할) >── 농장(Farm)
                                                   │  위치(위경도) → 기상 예보 조회
                                                   ├─ 밭(Field)             ← 물리적으로 떨어진 필지
                                                   │   └─ 구역(Zone)        ← 이랑/두둑 묶음, 과수 열 등
                                                   │       ├─ 장치(Device)   ← 토양 센서, (2단계) 관수 밸브
                                                   │       └─ 재배(Planting) ← 어떤 작물을 언제 심었는지
                                                   ├─ 게이트웨이(Gateway)   ← 현장 장치들을 서버에 연결
                                                   ├─ 공용 장치             ← 기상 센서, (2단계) 지하수 펌프
                                                   └─ 작물 프로필(Crop)     ← 이 농장이 직접 입력한 작물 기준값
```

- 한 사용자는 **여러 농장**에 속할 수 있고, 한 농장에는 **여러 사용자**가 역할(소유자/작업자/조회)을 가지고 참여한다.
- 모든 데이터는 **농장 단위로 격리**된다. 다른 농장의 데이터는 조회·수정할 수 없다.

### 시스템 구성

```
[1단계]  [장치 시뮬레이터] ─┐
                            ├── 장치 통신 규격 ── [JinFarm 서버] ── [웹 대시보드]
[이후]   [게이트웨이 ─ 센서 노드] ┘                     │    │    │
                                                      [DB] [기상청 API] [카카오톡]
```

### 우선순위 표기

| 표기 | 의미 |
|---|---|
| **P0** | MVP 필수 — 1단계에서 반드시 구현 |
| **P1** | 1단계 이후 바로 추가 / 2단계(관수) 핵심 |
| **P2** | 여유 있을 때 / 확장 기능 |

작물 정보는 시스템이 기본값을 제공하지 않고 **각 농장이 직접 등록**한다.
모든 기준값은 선택 입력이며, 입력한 값만 알림·자동 제어에 사용한다.

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| CRP-01 | 작물 등록 | 이름, 품종, 분류(과수/채소/…), 메모, 사진 | P0 |
| CRP-02 | 작물 유형 | **일년생**(상추·양파·수박 등, 심고 수확하면 끝) / **다년생**(살구·포도 등, 여러 해 유지) | P0 |
| CRP-03 | 기준값 입력 | 적정 토양수분 범위, 저온 한계(서리 피해), 고온 한계 | P0 |
| CRP-04 | 생육 단계 정의 | 사용자가 단계 이름·기간을 자유롭게 정의<br>- 일년생 예: 파종 → 육묘 → 정식 → 생장 → 수확<br>- 다년생 예: 휴면 → 발아 → 개화 → 결실 → 수확 → 낙엽 (**매년 반복**) | P1 |

> **카카오톡 발송 방식 참고**
> - **나에게 보내기**: 카카오 로그인한 사용자가 메시지 전송 권한에 동의하면 본인 카톡으로 무료 발송. 사업자 등록 없이 바로 쓸 수 있어 1단계에 적합.
>   단, 사용자별 카카오 토큰을 저장·갱신해야 하고, 토큰이 만료되면 발송이 실패하므로 재동의 안내가 필요하다.
> - **알림톡**: 여러 농가 대상 정식 서비스의 표준 방식. 사업자·채널·템플릿 심사·건당 비용이 필요하므로 서비스가 커진 뒤 전환한다.
> - 발송 방식은 인터페이스 뒤에 숨겨서, 나중에 알림톡으로 바꿔도 알림 로직은 그대로 두도록 설계한다.

| CUL-05 | 수확 기록 | 수확일, 수확량(kg/개/박스), 품질 메모 — 다년생은 연도별 누적 | P1 |
| CUL-06 | 개체 관리 | 과수를 그루 단위로 식별·기록 (나무별 수세, 수확량) | P2 |
| CUL-07 | 연작 이력 | 구역별 과거 재배 작물 조회, 연작 경고 | P2 |
| CUL-08 | 통계 | 작물별·구역별·연도별 수확량, 날씨와 수확량 비교 | P2 |

### 2.7 관수 제어 (2단계)

관수 설비(스프링클러/점적, 구역별 밸브) 결정 후 구현한다. 1단계에서는 도메인 모델만 확장 가능하게 설계해 둔다.

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| IRR-01 | 수동 관수 | 대시보드에서 구역 선택 → N분 관수 (지하수 펌프 + 해당 구역 밸브) | P1 |
| IRR-02 | 제어 이력 | 누가·언제·어느 구역을·얼마나·왜(수동/자동/스케줄) 관수했는지 | P1 |
| IRR-03 | 안전 제한 | 최대 연속 관수 시간, 통신 끊기면 밸브·펌프 자동 정지 (현장 측) | P1 |
| IRR-04 | 스케줄 관수 | 구역별 요일·시각·시간 지정 | P1 |
| IRR-05 | 토양수분 기반 관수 | 작물 기준 이하 → 관수, 기준 이상 → 정지 (히스테리시스 포함) | P1 |
| IRR-06 | 비 오면 건너뛰기 | 강우 감지 또는 예보상 강수 시 관수 생략 | P1 |
| IRR-07 | 동시 관수 제한 | 지하수 펌프 용량을 넘지 않도록 밸브 순차 개방 | P2 |
| IRR-08 | 물 사용량 | 유량계로 구역별 관수량 측정 | P2 |
| IRR-09 | 관수 이상 알림 | 관수했는데 토양수분이 오르지 않음 (배관 막힘·누수 의심) | P2 |

### 2.8 장치 시뮬레이터 (개발·시연용)

실제 장비 없이 전체 기능을 개발·시연하기 위한 가짜 장치.

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| SIM-01 | 가상 장치 | 농장에 등록된 장치마다 가상 장치를 만들어 주기적으로 데이터 전송 | P0 |
| SIM-02 | 동일 규격 | 실제 장비와 같은 통신 규격·장치 인증 키 사용 (서버는 가짜/진짜를 구분하지 않음) | P0 |
| SIM-03 | 현실적인 값 | 하루 기온 변화(낮에 오르고 밤에 내림), 시간이 지나며 토양수분 감소, 비 오면 토양수분 상승 | P0 |
| SIM-04 | 시나리오 | 버튼으로 이상 상황 발생: 가뭄(토양 건조), 서리, 폭염, 장치 오프라인, 배터리 저하 | P0 |
| SIM-05 | 과거 데이터 생성 | 그래프 확인용으로 지난 N일치 데이터를 한 번에 생성 | P1 |
| SIM-06 | 시간 배속 | 하루를 몇 분으로 압축해 알림·그래프를 빠르게 확인 | P1 |
| SIM-07 | 관수 반응 | (2단계) 밸브를 열면 해당 구역 토양수분 상승 | P1 |
| SIM-08 | 운영 환경 차단 | 시뮬레이터는 개발·시연 모드에서만 켜지고, 운영 환경에서는 비활성화 | P0 |

## 3. 단계별 범위

### 1단계 — MVP (P0): 보고, 알고, 기록하기 (시뮬레이터 기반)

1. 카카오 로그인, 농장 생성·전환, 농장 단위 데이터 격리
2. 농장(위치) · 밭 · 구역 · 장치 등록, 장치 인증 키, 장치 상태
3. 작물 프로필 직접 등록 (일년생/다년생, 기준값) + 구역에 작물 심기
4. 토양수분·토양온도 + 현장 기온·습도·강우 수집, 기상청 예보 연동
5. 대시보드 + 이력 그래프
6. 알림: 토양 건조, 장치 오프라인·배터리, 서리·폭염 등 기상 경보 → 웹 + 카카오톡(나에게 보내기)
7. 장치 시뮬레이터 + 이상 상황 시나리오

### 1.5단계 — 서비스 다듬기

멤버 초대·역할, 알림 설정, 생육 단계, 영농 일지·수확 기록, 지도 보기, 시뮬레이터 과거 데이터·배속

### 2단계 — 실제 장비 + 관수 제어

게이트웨이·센서 노드 제작 및 현장 통신 방식 결정, 장치 페어링, 지하수 펌프·밸브 연동, 수동/스케줄/토양수분 기반 관수

### 이후

카카오 알림톡 전환, AI 작물 정보 가져오기, 작물 프로필 공유, 통계, 서비스 관리자 화면
